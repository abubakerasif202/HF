## Architecture and technical audit

- Public pages are server-rendered/static Next.js routes driven by `lib/site-data.ts` and `lib/hf-service-areas.ts`; the catch-all has exact segment guards. Dedicated area routes handle the locality inventory. No pagination or indexable search/archive parameter routes were found.
- All **168 live sitemap URLs** returned 200 with exactly one H1, canonical, title and description. Titles/descriptions were unique and JSON-LD parsed. The baseline local crawl also found no broken internal URLs, orphans, invalid sitemap URLs or page failures.
- Canonical production origin is **https://www.hfremovalsadelaide.com.au**. HTML canonicals, sitemap, social metadata, schema and breadcrumbs use it. Relative internal links resolve on the redirected preferred host. Query-bearing commercial URLs retain their query-free canonical.
- HTTPS apex redirects permanently to www. HTTPS legacy contact/about/interstate/blog paths and trailing slashes normalize directly to their canonical replacement; query strings survive. Unknown paths and extra catch-all segments return genuine 404s.
- HTTP apex first receives Vercel's same-host HTTPS upgrade, followed by the application hostname/path redirect. HTTP www legacy paths also require HTTPS upgrade then path normalization. **A complete one-hop HTTP normalization requirement remains unmet at the hosting layer.** Do not replace the working apex configuration with a generic domain redirect: that would reintroduce chains for HTTPS legacy paths. Application redirects cannot override an earlier platform response.
- Robots allows public content/assets and excludes admin/API paths. Public booking/success/cancel/job-completion pages emit noindex and remain crawlable; utility pages are excluded from the sitemap. No crawler asset blocking or mixed-content source URL defect was identified.
- Existing MovingCompany, WebSite, Service, WebPage, Article, CollectionPage, ItemList, BreadcrumbList and visible FAQ schema remain. No ratings, awards, prices or hours were invented. Inner-page entity references are valid; no duplicate shared business graph was added.
- Most imagery already uses responsive WebP/Next Image or responsive picture sources, descriptive alt text and reserved dimensions; hero images are eager/high priority and lower-page imagery is lazy. Slow-scroll browser inspection exposed four remaining raw homepage service-card images; these now use the existing responsive Next Image component. No dependency, CSS layout or animation changes were needed. Real-user LCP/CLS/INP still require CrUX/GSC evidence.
- Existing mobile menu, quote loading/error/success handling, timeout/duplicate-submit protection, tel links and booking CTAs remain. Regression validation uses mocked quote-provider responses; no customer lead or booking is submitted.

## Location pages and remaining risks

The existing 139 area pages include editorial profiles and regional fallbacks. Many fallback sections/FAQs still repeat regional planning advice. No mass generation, deletion, noindex or consolidation was performed: the supplied aggregate export is insufficient to establish which ranking URLs can safely be retired. Improve selected pages only with verified useful locality/access evidence; do not manufacture local operational claims. No supplied business facts were changed.

CTR/ranking improvements are expected outcomes, not guarantees. Historical GSC totals are not a diagnosis of today's indexing or Google-selected canonical. Browser lab checks do not establish real-user Core Web Vitals. Google may rewrite snippets and FAQ markup does not guarantee a rich result.
